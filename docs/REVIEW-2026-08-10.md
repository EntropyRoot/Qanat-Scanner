# External review, 2026-08-10

An outside reviewer built the tree with Clang and GCC under
`-Werror -Wconversion -Wsign-conversion`, ran every suite, ASan and UBSan, and
the 18-case OpenSSL interoperability matrix. All passed. The findings below
are what survived that.

Their verdict: senior-level systems work, not yet a release that has been
through a senior review. Four items are called release blockers.

This file records the findings and my own assessment of each. Several are
mine, introduced during the rebuild; those are marked.

**Status: every item below is fixed.** What each fix was, and how it was
shown to work, is in `## Outcome` at the end.

## Blockers

### 1. `getrandom` assumed present from the header alone

`src/core/perm.c:10-14, 89-106`. The code treats `__has_include(<sys/random.h>)`
as proof the function is declared, which is not true across bionic and Termux
versions. The reviewer hit the real build error on Termux.

`src/crypto/rand.c:50-64` already does this correctly through
`syscall(SYS_getrandom, ...)`. So there are two entropy paths and the older
one breaks the primary target.

**Assessment: credible, act on it.** Our NDK build at API 30 worked, which is
exactly why this went unnoticed. Fix by giving both callers one helper. CI
only builds Ubuntu and `aarch64-linux-gnu-gcc`, which is glibc, not bionic —
an Android-first project should have a real NDK or Termux build in CI.

### 2. Data discarded when epoll reports `EPOLLIN` together with `EPOLLERR`

`src/net/engine.c:591-631, 723-733`. Both collapse into flags, and
`dispatch_probe()` handles the error branch first, closes the socket, and
drops readable bytes. Reproduced by the reviewer: flags `0x201d`,
`SO_ERROR = ECONNRESET`, and 25 bytes still queued. The select backend kept a
banner the epoll backend lost.

Second defect in the same branch: `if (!err) err = ECONNRESET;` invents a
reset for a `EPOLLHUP` with no error, which can be a clean EOF.

**Assessment: credible and important.** This is well-known Linux behaviour and
the reproduction is specific. It matters beyond banners: a short TLS alert
could be misfiled as a reset. Drain until `EAGAIN` first, then check
`SO_ERROR`, and treat HUP with no error as EOF.

### 3. Retry re-calls `next()`, but the sweep is no longer pure — **mine**

`src/net/engine.c:558-585`, `src/task/task_cf.c:38-56`,
`src/core/bandit.c:117-188`. When `probe_launch()` fails the worker rewinds
`claim_cur` and calls `next()` again. That is only sound if `next()` is
replayable.

It was, until I wired the bandit in. `cf_next_sweep()` now calls
`qn_bandit_next()`, which bumps the block's `drawn`, bumps `issued`, and
claims an address permanently. On retry the original address is never probed.
The reviewer reproduced it: same step, two different addresses, `issued = 2`.

**Assessment: confirmed, and it is my regression.** Before the bandit the
sweep used `qn_perm_apply`, which is pure; I made it stateful and did not
notice the engine depended on purity. It also contradicts the coverage claim
under exactly the resource pressure this tool targets (`EMFILE`, `ENOBUFS`).
Fix by holding the produced job as `pending_job` and retrying that job, not by
calling `next()` again. Rolling the bandit back across workers would be racy.

### 4. Receive deadline is armed from a stale clock

`src/core/timewheel.c:30-55`, `src/net/engine.c:373, 407-427, 709-741`. The
comment says the receive deadline measures the peer, but `qn_tw_arm()` builds
it from `w->now_ms`, which has not been advanced past the connect wait. A
250 ms receive budget can become 50 ms. `QN_STAGE_BANNER` arms no receive
deadline at all.

**Assessment: plausible and specific; verify first.** I changed
`qn_tw_next_timeout` this cycle but not `qn_tw_arm`. Fix by passing real time
in, or refreshing the wheel clock before re-arming.

## High

### 5. The "complete" sweep always skips 30 addresses

`src/core/cidr.c:11-19, 151-177`. Every IPv4 prefix shorter than /31 loses two
addresses, network and broadcast. That is right for a LAN and wrong for a BGP
aggregate: the first and last address of a Cloudflare range are usable.

**Assessment: confirmed by our own output.** Device runs printed a domain of
`1524706`; the reviewer computes the true total as `1,524,736`. The 30
missing addresses are exactly two per each of the 15 prefixes. Make the
iterator cover everything and make host-exclusion an opt-in policy for local
discovery.

### 6. Stop and restart can deliver stale events into the new task

`src/net/engine.c:874-918, 957-1009`, `src/ui/app.c:884-899`. `qn_engine_stop()`
joins workers but never drains or resets the rings, and the UI polls once with
a budget of 8192 while sixteen workers can hold roughly 16,384 events. A
leftover event is then handed to the new task's callback and context.

**Assessment: credible; the reviewer did not reproduce it end to end.** Drain
or reset every ring after join, and make "all rings empty" an explicit
precondition of start.

### 7. A truncated or malformed range file is accepted silently

`src/task/task_cf.c:188-197`, `src/core/cidr.c:110-133`. Capacity is 128 and
the loader returns true if any single line parsed. 129 valid lines yield 128;
two valid lines plus one broken line yield 2, with no warning.

**Assessment: credible and easy to verify.** Silent narrowing of the target
set is bad in a measurement tool. Report accepted, rejected, the offending
line, and overflow; fail closed by default.

## Smaller, still real

- **Short banners count as timeouts.** `src/net/engine.c:429-435` requires 32
  bytes for completeness, so a responsive peer sending `HELLO\r\n` is recorded
  as a timeout, which pollutes statistics and AIMD.
- **`--seed` accepts garbage — mine.** `src/main.c:173-177` uses `strtoull`
  with no `endptr` or `errno` check, so `garbage` becomes 1 and `-1` becomes
  `UINT64_MAX`, while every other numeric flag is strict.
- **History and event-log failures are silent.** `src/task/task_cf.c:345-365,
  430-437`. A file called an audit log must not fail quietly.
- **AES key length is not validated.** `src/crypto/aesgcm.c:81-99`. Every
  current caller passes 16 or 32, so no live path is affected, but `nk` could
  reach zero and `i % nk` would divide by zero. Harden the API.

## Dead weight to remove

- `CF_PHASE_HTTP` exists with a label but the state machine skips it.
- `QN_STAGE_HTTP` branches remain though no task emits such a job.
- `cf_scan.perm` is initialised and never read — **mine**, left behind when
  the sweep moved to the bandit.
- `phase_domain` is written in all three tasks and never read.
- `qn_bandit.exhausted` is neither read nor written — **mine**.
- `qn_spark.max` is maintained but the renderer recomputes it.
- `qn_p256_keypair()` and `qn_p256_ecdh()` are declared with no
  implementation — **mine**. Calling them is a link error. Either implement
  P-256 or delete the declarations.
- CI runs four fuzz targets; the Makefile builds six — **mine**. `fuzz_http1`
  and `fuzz_http2` are never exercised there.

## Suggested order

1. The four blockers, each with a regression test that fails before the fix
2. CIDR coverage, restart lifecycle, range loader, likewise with tests
3. The smaller correctness items
4. Delete the dead weight, and either implement P-256 or drop its header

A real NDK or Termux build in CI would have caught finding 1 and belongs in
the same patchset.

The reviewer saw a snapshot without `.git`, so commit history and how review
feedback was handled could not be judged. Nothing in the findings depends on

## Outcome

### Blockers

1. **getrandom.** Both entropy paths collapse into `qn_os_entropy` in
   `src/core/util.c`, over `syscall(SYS_getrandom, ...)` with `/dev/urandom`
   behind it and `EINTR` handled on both. `perm.c` no longer guesses from
   `__has_include`. CI now builds with the NDK at API 24 and 30, which is the
   part that would have caught it.

2. **EPOLLIN with EPOLLERR.** `dispatch_probe()` drains to `EAGAIN` before it
   looks at `SO_ERROR`, so queued bytes survive the error that arrived with
   them. `EPOLLHUP` is its own flag now: a hangup with no pending error is an
   EOF, and whatever arrived gets classified instead of being called a reset.
   A connecting socket keeps the old meaning, since there is nothing to
   salvage there. Found alongside it: with edge triggering, a reply that
   landed mid-send was never read, because `EPOLLIN` is not re-reported. The
   send path now re-checks for readability after it transitions.

3. **Retry called next() again.** Workers hold the produced job as
   `pending_job` and retry that. Covered by `test_engine.c`, which lowers
   `RLIMIT_NOFILE` so every launch has to fail: against the old code
   34 of 384 addresses were never probed. A job that cannot launch with
   nothing else in flight is retried 64 times and then reported as an error
   event, so `issued` and `completed` stay balanced instead of wedging.
   `test_props.c` also pins the premise: one bandit step drawn twice
   consumes two addresses.

4. **Stale clock.** Verified, and it was as described. `qn_tw_arm()` takes
   `now_ms` from the caller and advances the wheel with it, so the shape of
   the bug cannot recur at a new call site. The worker samples the clock
   again after `epoll_wait`/`select` return. `QN_STAGE_BANNER` now arms its
   own receive budget.

### High

5. **CIDR coverage.** `qn_prefix_hosts()` returns the full span;
   `qn_prefix_usable()` and `qn_cidr_set_skip_edges()` make exclusion an
   opt-in policy. On the device the sweep domain now prints 1,524,736.

6. **Restart lifecycle.** An empty ring is an explicit precondition of
   `qn_engine_start()`, enforced by `qn_ring_reset()`. Draining at stop was
   the other option and would have thrown away real partial results, so the
   UI drains in a loop after cancelling instead of taking one budget.
   Reproduced first: the second task received 448 events for 384 addresses.

7. **Range file.** `qn_cidr_set_load_file()` fills a `qn_cidr_report` and
   fails unless every non-comment line parsed and fitted. The set is sized
   from the file, so the old 128 ceiling is gone.

### Smaller

- Short banners: `on_timeout()` reports what arrived as an answer, timed from
  the first byte, rather than as a timeout.
- `--seed` goes through a strict `arg_u64`, which also rejects the sign
  `strtoull` would have wrapped.
- History and event-log failures land in `cf_scan.io_warn`, which the TUI
  shows in the status line and `--headless` prints and exits non-zero for.
  Warning straight to stderr would have scribbled over the TUI.
- `qn_aes_gcm_setkey()` rejects any length that is not 16 or 32, including
  AES-192, which Qanat does not expose; `qn_aead_init()` propagates rejection.

### Dead weight

`CF_PHASE_HTTP`, `QN_STAGE_HTTP` and its engine branches, `cf_scan.perm`,
`phase_domain` in all three tasks, `qn_bandit.exhausted`, `qn_spark.max` and
the `qn_p256_*` declarations are gone. CI runs all six fuzz targets.

`qn_cpu_has_sha512()` went with them: it advertised a dispatch that does not
exist. Whether to write the kernel instead was decided on a measurement —
see the benchmark table in `HANDOFF.md`.

### Checked against

Strict GCC build, all seven suites, numeric-menu PTY scenarios, GCC's
path-sensitive whole-program analyzer, ASan+UBSan, TSan, the six fuzz
harnesses (120,000 smoke inputs), and the 18-case OpenSSL matrix are clean on
the current checkout. A separate GCC audit with the format-overflow,
format-truncation, null-dereference, duplicated-logic, logical-op, alloca and
VLA warnings promoted to errors is also clean.

The current schema-3 checkout cross-compiles with NDK r27c at both API 24 and
30 as an AArch64 PIE. The API-24 artifact contains the AES, GHASH, SHA-256 and
four-way ChaCha assembly entry points. It was not executed on a handset because
no Android device was attached at the final checkpoint. The earlier
pre-schema-3 revision was compiled natively in Termux and exercised on the
ARM64 handset; see `HANDOFF.md` for the exact boundary and retained evidence.
